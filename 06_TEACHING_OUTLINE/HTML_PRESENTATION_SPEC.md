# HEART-LAB｜HTML 互動式教學簡報規格書

> 本文件定義後續 HTML 教學簡報的內容、畫面、互動、技術與驗收標準。這是開發規格，不是 HTML 成品。

## 1. 專案定位與製作範圍

- 專案名稱：心動研究所｜從心理學看追星文化
- 英文副標：THE PSYCHOLOGY OF FANDOM
- 核心提問：我們為什麼會對一個可能永遠不認識自己的人，產生這麼多情感？
- 主要案例：K-pop 粉絲文化；必要時補充一般偶像、媒體人物與網路社群研究。
- 目標對象：沒有心理學背景的一般讀者與學生。
- 主要語言：繁體中文；專有名詞第一次出現時附英文全名或縮寫。
- 教學時間建議：25–35 分鐘；可獨立瀏覽，不要求一定跟著講者操作。
- 主要交付：一個可由 GitHub Pages 開啟的互動式 HTML 簡報網站。
- 本階段不交付：研究資料庫改寫、登入系統、雲端資料庫、影音串流、個人資料蒐集。

## 2. 教學體驗與故事主線

以「從第一次注意，到產生情感連結，再走進粉絲社群，最後學會保有自主」作為敘事主線。

1. 好奇：我什麼時候開始注意一個人？
2. 熟悉：為什麼會想持續看見他的內容？
3. 連結：為什麼明明不認識，卻會感覺熟悉？
4. 歸屬：喜歡同一個人，如何讓陌生人相遇？
5. 拉扯：快樂、期待、錯過焦慮與消費壓力如何並存？
6. 判讀：研究可以告訴我們什麼，又不能告訴我們什麼？
7. 帶走：如何保留喜歡的快樂，也保有自己的生活？

語氣必須溫柔、中立、不嘲笑粉絲，也不把所有追星行為浪漫化。不要使用「追星就是成癮」「粉絲都很盲目」等污名化說法。

## 3. 視覺與版面系統

### 3.1 視覺方向
- 主題：夢幻藍粉色的演唱會研究手帳。
- 主色：深夜藍、霧藍、淡薰衣草紫、柔粉；重要資訊以高對比深色文字呈現。
- 背景元素：柔和漸層、星點、舞台光束、拍立得邊框、票根、研究筆記貼紙、小卡收納感。
- 裝飾只作為氣氛，不可壓過文字、研究圖表或互動控制。
- 避免整頁滿版照片、過多閃爍、快速移動背景與難以閱讀的細字。

### 3.2 版面規則
- 以 16:9 投影片畫布為桌面主要比例；內容置中，保留安全邊界。
- 一頁只傳達一個主要觀念；標題、主訊息、例子／圖解、來源註記分層。
- 每頁主要文字建議 30–60 個中文字；研究說明頁可稍多，但必須分段或卡片化。
- 內文建議至少 18px；來源與註腳不得小於 14px。
- 手機版改為單欄垂直閱讀，不可把 16:9 畫面直接縮小到看不清楚。
- 所有按鈕、卡片與可互動物件需有清楚的文字標籤，不可只靠顏色辨識。

### 3.3 動畫原則
- 轉場以淡入、滑入、卡片翻面等短動畫為主，建議 150–350ms。
- 不使用持續閃爍、快速縮放或會干擾閱讀的粒子動畫。
- 支援 prefers-reduced-motion；使用者要求減少動態效果時，停用非必要動畫。

## 4. 簡報資訊架構與頁面清單

建議共 30 頁，包含封面、七章內容、互動練習與結尾。頁數可因教學節奏微調，但七章核心概念與研究限制不可刪除。

|---|---|---|---|
| 01 | 封面：心動研究所 | 專案名稱與核心提問 | 演唱會光點、主標題、開始探索按鈕 |
| 02 | 研究任務 | 說明這不是要判斷誰追星追得對，而是理解情感如何形成 | 研究任務卡、七站探索路線 |
| 03 | 你從哪裡開始心動？ | 舞台、聲音、個性、陪伴感、朋友推薦等不同入口 | 點選入口後顯示一段回應；不儲存答案 |

## 5. 互動元件詳細規格

### 5.1 全站導覽
- 提供上一頁、下一頁、章節選單與目前頁數／總頁數。
- 進度條顯示整體進度，章節選單標示目前所在章節。
- 支援鍵盤左右方向鍵切換頁面；輸入框、按鈕與選單取得焦點時，不攔截方向鍵輸入。
- 支援 Home 回到第一頁、End 前往最後一頁；若與瀏覽器或輔助技術衝突，優先保留一般鍵盤操作。
- 重新整理頁面時可回到封面，或以 URL hash 保留目前頁碼；不得要求登入。

### 5.2 情境分類互動
- PSI／PSR 至少 3 題，每題提供兩種選擇。
- 作答後立即顯示正確分類、理由與一個容易混淆的地方。
- 提供重新作答，不只顯示紅／綠顏色；文字必須明確說明結果。
- 不將答題表現轉換成心理狀態、人格或追星程度評分。

### 5.3 研究判讀小測驗
- 至少 3 題，涵蓋 PSI／PSR、相關與因果、研究樣本限制。
- 每題至少 2 個選項，答題後顯示答案與白話解釋。
- 最後顯示答對題數，不設排行榜、不蒐集個人資料。
- 提供再測一次按鈕。

### 5.4 個人反思輸入
- 提供一個可輸入「我的追星界線提醒」的文字欄位。
- 提供複製按鈕與清除按鈕。
- 不連接資料庫、不上傳、不寫入第三方服務；關閉或重新整理後不保證保留。
- 必須讓使用者知道文字只在目前瀏覽器頁面中暫時使用。

### 5.5 研究來源卡
- 每張研究卡顯示作者與年份、研究對象／樣本、研究方法、可支持的主張、主要限制。
- 可展開 DOI、期刊或論文頁面連結；外部連結需另開新分頁並標示。
- 不可只顯示作者結論而隱藏樣本與限制。
- S012 必須註明自我控制調節係數與作者文字解讀存在疑點，不可將緩衝效果當成確定結論。

## 6. 研究證據與引用規則

- 每個研究主張旁或該頁底部顯示來源代碼，例如 [S010]。
- 點擊來源代碼可開啟簡短研究卡；研究卡提供正式來源頁連結。
- 研究數字需同時標示樣本、國家／情境與研究方法，避免脫離脈絡。
- 相關性、迴歸、中介模型與橫斷式問卷不得寫成已證實因果。
- 一般心理學研究不得描述成 K-pop 專屬證據。
- 質性研究用來說明經驗，不可用來推估盛行率。
- S003 為小樣本質性碩士論文；S004 僅 3 位高 FoMO 參與者；S012 為印尼周邊購買者問卷；S013 為美國 CD 購買者問卷。
- S012 自我控制調節結果存在係數符號與作者文字解讀不一致的疑點，簡報必須保留此限制。
- 健康追星的時間、金錢與情緒界線屬於根據研究整理的實務建議，不得宣稱為單篇研究驗證的固定療法。

## 7. 技術實作規格

- 建議採用原生 HTML、CSS、JavaScript，避免需要建置流程的框架，降低 GitHub Pages 部署複雜度。
- 主要入口檔：index.html；樣式與互動可分為 styles.css、script.js；若後續需要，也可拆分 data.js。
- 不使用登入、資料庫、追蹤像素、分析 SDK 或任何使用者資料蒐集服務。
- 核心內容應在沒有網路連線時仍可閱讀；外部來源連結除外。
- 不依賴外部 CDN 才能完成主要導覽與測驗；字型與圖示應有本機或系統字型備援。
- 內容與互動邏輯分離，研究來源資訊集中管理，避免同一來源在多頁出現不同版本。
- 所有圖片需有合理替代文字；純裝飾圖使用空替代文字。
- 使用語意化 HTML，互動控制需有可讀標籤與可見焦點。

## 8. 無障礙與響應式驗收

- 全站可使用鍵盤完成導覽、答題、展開來源卡與複製／清除文字。
- 焦點順序符合畫面閱讀順序，焦點樣式清楚可見。
- 文字與背景需有足夠對比；不可只靠顏色表達正誤或分類。
- 圖片提供替代文字；按鈕有明確名稱；表單輸入有標籤。
- 支援 prefers-reduced-motion。
- 在桌面寬螢幕、平板與手機寬度測試，不可出現水平溢位或被切掉的控制。
- 手機版點擊區域需足夠大，文字不因縮放而難以閱讀。

## 9. 功能與品質驗收清單

### 導覽與版面
- [ ] 封面開始按鈕可進入第一章。
- [ ] 上一頁／下一頁、章節選單與進度提示一致。
- [ ] 30 頁均可抵達，沒有空白頁或重複頁。
- [ ] 桌面、平板、手機版均無水平溢位。
- [ ] 字體大小、對比與安全邊界符合規格。

### 互動
- [ ] PSI／PSR 情境分類至少 3 題，答後有正確解釋。
- [ ] 研究判讀測驗至少 3 題，分數計算正確且可重做。
- [ ] 研究來源卡可展開與收合，外部連結正確。
- [ ] 反思文字可輸入、複製與清除，且不會上傳。
- [ ] 鍵盤導覽與焦點狀態正常。

### 內容與證據
- [ ] 每個重要研究主張都有來源代碼。
- [ ] 研究樣本、方法、結果與限制沒有張冠李戴。
- [ ] 沒有把相關寫成因果，也沒有把單一樣本推廣到所有粉絲。
- [ ] S012 調節結果疑點有清楚揭露。
- [ ] 正向粉絲經驗與可能壓力都被平衡呈現。

### 部署與瀏覽器測試
- [ ] GitHub Pages 可正常載入，不依賴本機絕對路徑。
- [ ] 重新整理、直接開啟頁面與瀏覽器返回操作不會造成錯誤狀態。
- [ ] Chrome、Edge 與手機瀏覽器完成基本檢查。
- [ ] Console 無阻斷功能的 JavaScript 錯誤。
- [ ] 所有內部連結、來源連結與圖片路徑均可用。

## 10. 開發順序與回退機制

1. 先建立全站版型、色彩、字體、導覽與空白頁面骨架。
2. 完成封面、章節導覽與上一頁／下一頁，先測試導覽狀態。
3. 依七章順序填入已查核內容與研究來源卡。
4. 加入 PSI／PSR 情境分類、研究判讀測驗與反思輸入。
5. 完成響應式、鍵盤操作、減少動態效果與來源連結測試。
6. 部署 GitHub Pages，實際使用桌面與手機瀏覽器驗收。
7. 記錄測試結果、錯誤與修正，才標記為完成。

回退規則：若內容查核失敗，回到 Wiki／來源核對；若互動測試失敗，回到該元件實作；若部署失敗，先檢查路徑與 GitHub Pages 設定，不以刪除研究內容作為修復方式。

## 11. 完成定義

只有在七章內容完整、所有核心互動可用、來源可追溯、桌面與手機版通過測試、GitHub Pages 實際可開啟後，才可稱為「HTML 互動式教學簡報完成」。僅有畫面截圖或本機預覽不算完成部署。

## 12. 待開發時再決定的細節

- 是否增加講者備註／教學者模式。
- 是否提供列印友善版本。
- 是否在封面提供音效；預設不自動播放音樂或音效。
- 是否加入可選的章節快速跳轉目錄。
- 所有新增功能不得延誤基本可用性、研究正確性與手機閱讀品質。
